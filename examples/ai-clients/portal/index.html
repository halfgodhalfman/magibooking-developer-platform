Use the local OAuth helper, then configure a stdio server that forwards to the remote MCP endpoint. Configuration contains a private token-file path, never the token itself.

Give an OpenAI agent two read tools

The example allows only list_services and list_staff. Configure your model API key locally, obtain an MCP-audience token, then run the example.

node examples/ai-clients/openai.mjs --allow-provider-data

This sends your short-lived MCP token and test catalog results to OpenAI. Use a dedicated read-only grant. Provider model usage may incur charges.

Execute DeepSeek tool calls in your app

Your app calls the REST API, returning only the requested sandbox catalog results. The MagiBooking token stays local. Unknown tools and model-supplied URLs or merchant IDs are rejected.

node examples/ai-clients/oauth.mjs api
node examples/ai-clients/deepseek.mjs --allow-provider-data

Catalog and staff results go to DeepSeek. Configure DEEPSEEK_MODEL, DEEPSEEK_API_KEY, MAGI_AI_MERCHANT_ID and a separate REST-audience token file. Provider usage may incur charges.

MCP OR REST

Use the protocol your agent supports

For MCP clients, use Streamable HTTP, a preregistered OAuth client, S256 PKCE and the exact MCP resource audience. For other runtimes, use the REST SDKs and OpenAPI. REST and MCP tokens are not interchangeable.
